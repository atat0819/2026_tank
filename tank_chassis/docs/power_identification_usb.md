# 四轮 3508 功率辨识采集说明

当前功率辨识 VOFA 采集发送段已注释暂停，USB 现用力控调试通道，见 [四轮力控 VOFA 调试](chassis_force_vofa.md)。下文保留原采集模式说明；实际功率限制与功率计接收不受影响。

本固件用外接功率计测量四个 3508 的供电总功率，经 UART10 接收；CAN 任务采集四轮反馈后，通过 USB CDC 发送 VOFA JustFloat 数据。沿用遥控行驶采样，当前没有自动扫频动作。

## 接线和协议

- 功率计 TX 接主控 **PE2 / USART10_RX**，两端 GND 共地。当前采集仅接收，PE3 / USART10_TX 无需接功率计。
- 功率计通信设置为 **115200、8 数据位、无校验、1 停止位**。
- 沿用工程历史协议：每帧连续 12 字节，依次为小端 IEEE 754 float32 的电压 V、直流电流 A、输入功率 W。
- 此协议没有帧头和 CRC。短帧会被丢弃，完整帧检查浮点数有限性；协议不提供可靠的错位检测和重新同步。需要功率计实际输出与上述格式一致，并通过实采确认帧间隔。
- 电脑连接主控 USB 数据接口，在 VOFA 中选择对应虚拟串口与 **JustFloat**。USB 接收端的虚拟波特率不决定 UART10 的物理波特率。

## VOFA 通道

下面使用 1 开始的通道号；若 VOFA 显示从 0 开始，显示编号减 1。

| 通道 | 内容 | 单位 |
|---|---|---|
| 1 | 功率计实测四轮总输入功率 | W |
| 2、3 | ID 1：反馈电流、转子转速 | A、rad/s |
| 4、5 | ID 2：反馈电流、转子转速 | A、rad/s |
| 6、7 | ID 3：反馈电流、转子转速 | A、rad/s |
| 8、9 | ID 4：反馈电流、转子转速 | A、rad/s |
| 10 | 当前系数预测的四轮总输入功率 | W |
| 11 | 功率帧接收时间，HAL tick 转为秒 | s |
| 12 | 功率计直流电压 | V |
| 13 | 功率计直流电流 | A |
| 14 | 四轮在线位掩码，bit0..3 对应 ID1..4，全部在线为 15 | 无 |
| 15 | 有效功率帧序号 | 无 |

电机反馈电流保留正负号，是 C620 反馈换算后的转矩电流，与通道 13 的供电直流电流含义不同。转速直接取减速比为 1 的电机对象，属于转子端，没有除以行走轮减速比 15.8。

每个有效功率计新帧最多发送一帧，采样率由功率计决定；停车时仍采集。USB 未枚举或忙时跳过，不阻塞电机控制，序号间断可帮助发现丢样。功率计停止发帧后不会持续发送旧测量。

时间通道记录 UART 接收时刻，四轮反馈取自 CAN 任务处理该功率帧时刻；二者不是硬件同步采样，还存在功率计内部测量/滤波延迟。优先用稳态数据辨识；使用动态段时，需要先检查并补偿时延。

## 记录与拟合

先确认通道 12 的电压、通道 1 的功率符合功率计读数，通道 14 为 15。然后用遥控采集不同速度、正反向及负载的数据，导出全部通道 CSV；不需要为采集取消现有功率限制。

当前 `PowerControlBase` 的单电机输入功率模型为：

```text
P_i = K0 + K1*I_i + K2*abs(w_i) + K3*I_i*w_i + K4*I_i^2 + K5*w_i^2
```

总功率测量应使用四轮模型求和拟合：

```text
P_meter = 4*K0 + K1*sum(I_i) + K2*sum(abs(w_i))
        + K3*sum(I_i*w_i) + K4*sum(I_i^2) + K5*sum(w_i^2)
```

不能用一台电机的电流/转速去对应四轮总功率，也不能把总功率简单除以 4 来当作每轮实测功率。通道 10 使用当前旧系数，仅用于比较预测误差；新系数需要实际 CSV 才能得到。

拟合时排除离线、无效和异常采样；检查回归矩阵是否满秩。只采集对称直行时，`sum(I_i)` 可能接近零，无法可靠辨识 K1；其他项也可能因工况单一而相关。现有单电机三列拟合脚本不能直接套用这份四轮总功率数据。

## 实现与验证

- `RtosTask/remote_task.cpp`：UART10 接收、有效帧发布和错误恢复。
- `RtosTask/can_send_task.cpp`：四轮采样、模型求和及 USB VOFA。
- `RtosTask/up_stair.cpp`：原 UART10 IMU 遥测调用已关闭，滤波和控制保留。
- `Core/Src/usart.c` 和 `.ioc`：UART10 115200 配置。

主机测试覆盖 USB 缓冲区生命周期、忙/未连接、帧尾、UART HT/短帧/非有限数/错误恢复、四轮单位与模型求和、新帧去重和停车采集。HI14、IMU 滤波、RS485 错误恢复及上台阶驱动分配相关回归通过。

Keil `MDK-ARM/power_identification_usb_build.log` 记录 **0 Error(s), 5 Warning(s)**，AXF/HEX 已生成。代码审查未发现阻止交付的问题。尚未刷写或进行 USB 枚举、功率计接线与实车采样验证，也没有生成新辨识系数。
