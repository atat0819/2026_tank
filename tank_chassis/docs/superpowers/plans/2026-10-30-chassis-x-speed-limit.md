# Chassis X speed limit implementation plan

**Goal:** 用户已确认车体 X 目标速度限制在 ±2.56 m/s，摇杆全行程线性映射，推满才达到上限；Y 和旋转保持原倍率。旋转反馈暂不新增滤波，先观察实际噪声与力矩输出。

**Architecture:** 在 `can_send_task.cpp` 目标预处理处配置单独的 X 速度上限；以输入归一化满量程计算线性倍率，并在车体坐标和最终斜坡输出处限幅。保留现有输入选择、Y/旋转目标、反馈、功率/电流限制和停车链。

- [x] 新增主机测试，执行实际输入坐标变换、斜坡和力控目标代码；先确认原满杆超过 2.56 的失败。
- [x] 最小修改 X 轴映射和限幅，更新原轮方向/上台阶测试中引用任务片段的测试夹具。
- [x] 校验普通输入和键盘、前后半杆/满杆、越限输入、组合运动及坐标旋转；运行力控 VOFA/方向/保护回归并检查 Keil 构建日志。

上限约束目标速度，不保证惯性、坡道或外力下实际速度绝不超限，也不能单凭该上限认定电机不会过载。沿用用户当前工作区和已有未提交改动，不提交、不刷写。

验证：新测试先因原 5.3×0.707 倍率导致满杆超过 2.56 而失败；完成修改后，前后零、半杆和满杆线性映射、越界及组合输入限幅通过。另测共享 Y 增益为 0 时 X 独立映射仍有效；Y/旋转倍率、鼠标、四轮方向、上台阶状态、VOFA、力控和保护回归通过。

工作期间当前源码 X/Y 滤波配置变为 50 Hz，保留该配置并让相关测试从实际源码读取滤波参数。旋转反馈未增加滤波，待 VOFA 实测判断。Keil `MDK-ARM/chassis_x_speed_limit_build.log` 记录链接和 HEX 生成完成，0 Error(s), 5 Warning(s)；未刷写或实车验证。
