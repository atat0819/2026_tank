# 底盘 UI 与固定瞄准刻度

`RtosTask/UI_task.cpp` 在裁判系统在线且机器人 ID 有效时发送功率、血量及瞄准图形。原 PWR/MAX/BUF 的数据来源、名称和位置保持不变。血量读取 `ext_power_heat_data_0x0201.current_HP/maximum_HP`。

## 初始布局

- 图层 1：原有功率显示。
- 图层 2：左上侧 HP 标签、当前血量数字；血条边框 `(100,800)` 到 `(400,824)`。非零血量按当前值/上限填充，超过上限时只将血条长度限制为满格；数字保留收到的当前血量。上限为零时不计算比例，隐藏填充线。零血量删除填充线，恢复后重新添加。
- 图层 3：固定十字准星、三条距离线及标签。默认准星中心 `(960,540)`，三条距离线中心为 `(960,500)`、`(960,460)`、`(960,415)`。

**3m/5m/7m 标签与默认坐标均为未标定占位参数，不代表实际命中位置。**

## 标定参数

修改 `user/core/APP/Referee/RMRefereeSystemUI.hpp` 的 `RMRefereeSystemUI::AimConfig`，重新编译并烧录后生效：

| 参数 | 含义 |
| --- | --- |
| `CENTER_X`、`CENTER_Y` | 准星中心，同时作为所有刻度的参考原点 |
| `CROSS_HALF_WIDTH`、`CROSS_HALF_HEIGHT` | 准星横线、竖线的半长度 |
| `DISTANCE_MARKS[3]` | 每条距离线的标签、X/Y 相对偏移、半长度 |
| `LABEL_OFFSET_X`、`LABEL_OFFSET_Y` | 标签相对距离线右端的偏移 |

每条距离线配置顺序为 `{label, x_offset, y_offset, half_width}`，例如默认第一条为 `{"3m", 0, -40, 16}`。其中心为 `(CENTER_X+x_offset, CENTER_Y+y_offset)`；线长为 `2*half_width`。标签显示在该线右端再偏移 `LABEL_OFFSET_X/LABEL_OFFSET_Y` 的位置。

坐标系左下为 `(0,0)`，向右为 X 正方向，向上为 Y 正方向，画布为 1920×1080；负 Y 偏移会使刻度下移。调整时将线的两个端点和整个标签保留在画面内。

固定摄像头位置、画面缩放与常用弹速，在已知距离实射，记录命中时对应的图像位置，再修改各刻度偏移。几何中心不保证是实际命中点，各档距离也不要求等像素间距。

## 发送与恢复

所有三个显示模块共用至少 40 ms 的包间隔，连续发送不超过 25 包/秒。数值每个任务循环更新；循环末尾仍延时 200 ms，所以实际更新周期包含发送时间，初始化约需额外 0.45 秒，正常数值更新约为 280 ms 一次。

固定准星、距离线、标签和血条边框仅在初始化时添加；后续修改功率数字、血量数字及填充线。裁判系统掉线会清除本地初始化状态，恢复后重新添加。发送启动失败时保持待重试状态；UART DMA 启动成功不代表客户端确认收到。

客户端自行清空 UI 而裁判链路未断开时，可在 UI 任务上下文调用 `ResetPowerStatus()`、`ResetHealthStatus()`、`ResetAimGuides()` 请求重新添加；本次未分配额外遥控按键。UI 模块的样式和发送缓冲区由同一个 UI 任务使用。

UI 任务栈在 `Core/Src/freertos.c` 中从 256 words 增至 384 words（1536 字节）。Keil 静态调用图的 `ui_task` 深度约 1004 字节，栈配置额外留出任务切换及浮点上下文余量；实际栈高水位仍需上板观察。

## 验证

`python tests/chassis_ui_test.py` 编译真实任务、绘图与协议源码，检查初始图形、现有功率、动态血量比例、零值/未知上限、失败重试、断线恢复、tick 回绕的发送间隔，并改动参数后重新编译验证线上坐标。`python tests/referee_protocol_test.py` 覆盖原裁判协议及 DMA 发送回归。

宿主测试和编译不代替客户端显示检查或实射标定。
