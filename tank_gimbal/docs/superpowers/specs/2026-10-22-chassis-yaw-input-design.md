# 取消云台 Yaw 电机，转发底盘转向输入

用户最终确认：两个工程同步修改。使用两个 int16_t 转发摇杆 X 与最新 DT7 鼠标 X；底盘持续使用最新采样计算目标角速度，Pitch Y 继续单次消费角度增量。该最新状态方案替代此前的 X 一次性增量方案。

## 改动与验收

- FDCAN3 仅保留物理 ID8 的 Pitch 电机，对象槽 1。删除 ID7 的收发、使能重试、反馈及控制依赖。
- Pitch 仅使用编码器角度/角速度反馈，保留 FSM、重力补偿、机械限位及失联清零，不再切换 IMU 来源；控制器按下文用户确认方案改为主控角度 PID + MIT 速度控制。
- RS485 仍为 28 字节：2..3 为右摇杆 X（去 1024 中值并使用现有 66 计数死区，约 -660..660）；4..5 为最新 DT7 帧的鼠标 X 采样值。均为小端有符号 int16_t，保留原始正负号。
- 遥控档仅摇杆字段有效，双中键鼠档仅鼠标字段有效；失联时两个字段清零。S1/S2 仍由底盘执行停车策略。
- 云台直接发送 `RemoteData.mouse_x`：同一 DT7 帧在下一帧到来前可以被多包 RS485 重复发送；新 DT7 鼠标 X 为 0 时更新为 0。发送忙/启动失败不排队或累加旧 X，下次发送最新快照。Pitch Y 仍使用 `ConsumeMouseDelta()` 返回的累计量，只更新一次角度目标。失联或非键鼠来源的 X 字段为 0。
- 其余字段、CRC、DMA 忙保护及等待回复 2 ms 的策略不变。
- 旧 CAN 偏角接口保留为固定 0，不再访问电机。通用 Yaw 控制库保留，但本任务不再调用。
- 用户确认取消 IMU：删除 IMU 启动等待、UART7 DMA 接收/解析/重启与任务内 IMU 对象；保留 UART7 的底层外设配置和通用驱动。RS485 字节 16..23 保留位置并填 0，不能视为有效姿态。
- 禁用视觉接管和向视觉发送绝对姿态；USB 接收解析接口保留。双上在视觉不可用时沿用 FSM 的人工角度模式，遥控速度档位、双中键鼠及双下 STOP 保持原映射。
- 编码器角度是车体相对角，速度来自电机反馈。无法补偿车体俯仰；重力参考沿用 46.7 度安装水平零点与原补偿参数（幅值仍为 0），不进行重新标定或调参。
- 主机测试验证字节序、符号、输入切换、失联、CRC、DMA 忙保护、Pitch ID8 路由和保护；Keil 验证完整编译。无刷写和实车验证。

## 底盘配套修改（当前实现）

1. `communication/boards_communication_uart_485.hpp/.cpp`：`Chassis485Data` 使用 `int16_t right_stick_x, mouse_x`，从 2..3、4..5 解码；摇杆校验范围 +/-660，明确失联帧两个字段也要求为 0。
2. `RtosTask/can_send_task.cpp::Chassis485_ApplyData()`：摇杆和鼠标均覆盖保存最新值，不累加；非双中档的鼠标缓存为 0。固定相对偏角为 0，保留完整帧心跳及新鲜度判断。
3. `RtosTask/can_send_task.hpp/.cpp`：通信状态增加 `mouse_x`，GIMBAL 快照设置 `input.wz=right_stick_x/660.0f` 和 `input.mouse_x=最新缓存值`。公共快照可供行驶/爬楼任务重复读取，不会消费或清除鼠标值。
4. 行驶任务允许 GIMBAL 摇杆接入原 `-input.wz*c`；LOCAL/GIMBAL 键鼠共同使用 `-input.mouse_x*2*pi/180`，限幅 +/-4 rad/s，下一有效采样覆盖之前每周期保持使用。保留小陀螺优先及 STOP 最终零输出。不增加车体 Yaw 角度闭环。
5. 本地遥控仍优先，100ms 输入过期停车，切源首周期停车；新有效包重新覆盖状态。Z 跟随停用，输出兼容字段固定 false；`phase_comp` 固定为 0。
6. 原 IMU 字段 16..23 保留填 0，不能用作姿态/角速度反馈。接收机只接底盘时，当前回复链路只传裁判数据，未向云台转发遥控输入；Pitch 仍受云台自身遥控在线门控。

固定偏角为 0 对应枪管与车体正前方对齐；若装配存在固定夹角，应在底盘填入实测安装偏角。

## 编译边界修正

完整编译发现现有 `Core/Src/freertos.c` 包含三个 C++ 业务头，导致 C 编译器报 `namespace` / `<algorithm>` 错误。仅以等价 C 任务入口声明替代这三个包含，不改变任务创建、优先级、栈大小或 defaultTask 启用状态。

两端已同步为相同的新字段语义，帧长和 CRC 保留；原 float Yaw 偏角字段已替换为两个 int16_t。

发送的是最新鼠标采样快照，HAL_OK 仅为 DMA 启动；busy/error 后使用最新状态重试，不补发旧采样，不保证每个 DT7 样本都经 RS485 传递。

## Pitch MIT 速度控制（用户后续确认）

- J4340 参数以用户给定的 `Parameters(-3.14, 3.14, -10, 10, -27, 27, 0, 500, 0, 5)` 为准：位置 rad、速度 rad/s、力矩 N*m；该参数同时用于发送编码和反馈解码。主控力矩幅值同步为 27 N*m。
- 主控保留两个独立角度 PID：遥控 Kp/Ki/Kd=32/0.015/0，键鼠为 26.5/0/0；输入 rad，输出 rad/s。构造参数 max 直接使用 `PITCH_MAX_SPEED_RAD_S = 95 * pi / 180`，约 1.658 rad/s，同时复用为遥控速度档的 speed_scale。
- 删除主控遥控/键鼠角度内环速度 PID 及遥控单速度 PID。正常 MIT 发送位置=0、目标角速度=角度 PID 或速度档输出、Kp=0、Kd=当前输入源的独立参数，保留原重力前馈。`PITCH_REMOTE_MIT_KD` 与 `PITCH_KEYMOUSE_MIT_KD` 初值均为 1.3，可分别修改；MIT Kd 是电机速度反馈增益，并非将原主控带积分速度 PID 原样搬进电机。
- 电机自身故障保护不能代替云台行程保护，协议映射范围也不等于已读取确认的电机内部保护配置。用本周期编码器反馈估算 `Kd*(目标速度-反馈速度)+前馈`，执行与用户参数对齐的 +/-27 N*m 限幅及既有 FSM `Limit_Torque()`。若幅值保护修改了估算值，或当前处于启用的方向限位边界，本包改发 Kp=Kd=0、t_ff=受限力矩；离开保护条件后恢复 MIT 速度控制，不新增保护状态机。
- 下限处即使本拍估算力矩为零/正，也关闭 Kd，避免电机后续速度变化产生负力矩。上限沿用 `limit_upper_torque=0`，允许正力矩支撑；原目标回收策略不变。FSM 与发送保护均使用同一份 `pitch_current_angle` 弧度快照。
- STOP、启动保护及电机/遥控失联均清零 Kd、目标速度和前馈，保留既有恢复使能和重新锚定。RS485 帧格式不变。
- VOFA 六通道格式保留，第六通道改为受限估算力矩，不能作为电机实测力矩或电机内环运行期间的连续力矩保证；内部保护配置、负载效果和极性仍需实机验证。
